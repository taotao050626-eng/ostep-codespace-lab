## Q1. 用 SJF 和 FIFO 调度 3 个长度均为 200 的作业，计算响应时间和周转时间

**预测**：三个作业长度相同，SJF 没有"更短作业可插队"的空间，执行顺序必然与 FIFO 相同，两者平均指标一致。

**验证命令**：
```
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p FIFO -l 200,200,200 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p SJF  -l 200,200,200 -c
```

**结果（FIFO 与 SJF 完全相同，原始输出见 `data/q1_fifo.txt`、`data/q1_sjf.txt`）**：

| 作业 | 响应时间 | 周转时间 | 等待时间 |
|---|---|---|---|
| 作业0 | 0.00 | 200.00 | 0.00 |
| 作业1 | 200.00 | 400.00 | 200.00 |
| 作业2 | 400.00 | 600.00 | 400.00 |
| **平均** | **200.00** | **400.00** | **200.00** |

**解释**：作业等长 → 三种策略的选择顺序都是 0→1→2，所以 SJF 退化为 FIFO，指标完全一样。

## Q2. 同上题，但作业长度改为 100、200、300

**预测**：作业已按"最短在前"排列，SJF 的最短优先顺序恰好就是 0(100)→1(200)→2(300)，与 FIFO 一致。

**验证命令**：
```
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p FIFO -l 100,200,300 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p SJF  -l 100,200,300 -c
```

**结果（两者相同，见 `data/q2_fifo.txt`、`data/q2_sjf.txt`）**：

| 作业 | 响应时间 | 周转时间 | 等待时间 |
|---|---|---|---|
| 作业0 | 0.00 | 100.00 | 0.00 |
| 作业1 | 100.00 | 300.00 | 100.00 |
| 作业2 | 300.00 | 600.00 | 300.00 |
| **平均** | **133.33** | **333.33** | **133.33** |

**解释**：因为作业本身就是"最短先到"，SJF 的调度顺序与 FIFO 完全相同，所以平均周转/响应都一致。

## Q3. 同上题，但用 RR，时间片为 1

**预测**：RR 每跑 1 秒就切换，所以每个作业很快就能第一次运行（响应时间极小），但会因反复被抢占而完成很晚，周转时间变差。

**验证命令**：
```
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p RR -l 100,200,300 -q 1 -c
```

**结果（见 `data/q3_rr_q1.txt`）**：

| 作业 | 响应时间 | 周转时间 | 等待时间 |
|---|---|---|---|
| 作业0 | 0.00 | 298.00 | 198.00 |
| 作业1 | 1.00 | 499.00 | 299.00 |
| 作业2 | 2.00 | 600.00 | 300.00 |
| **平均** | **1.00** | **465.67** | **265.67** |

**解释**：RR(q=1) 把平均响应时间压到 1，但平均周转时间 465.67 明显高于 FIFO/SJF 的 333.33 —— 这正是"公平换性能"的权衡：小时间片换来响应时间，代价是周转时间。

## Q4. 什么类型的工作负载，SJF 与 FIFO 提供相同的周转时间？

**答**：当作业的到达顺序已经是**按长度升序（最短的作业先到）**时，SJF 的选择顺序与 FIFO 完全一致，两者周转时间相同。

- 特例：所有作业长度**相等**时，二者也必然相同（见 Q1）。
- 反例：如果先到的是长作业、后到的是短作业，FIFO 会出现**车队效应（convoy effect）**，周转时间变差；此时 SJF 通过先跑短作业显著改善周转（见 Q2 中"已排序"与 Q1 中"等长"两种情形）。

---

## Q5. 什么类型的工作负载和量子长度，SJF 与 RR 提供相同的响应时间？

**答**：当 **RR 的时间片 q 大于或等于最长作业的长度**时，RR 不会发生抢占（每个作业一次跑完），退化为按到达顺序执行的 FIFO。若此时作业已按最短优先排序，则 SJF 也按同一顺序执行，于是 SJF 与 RR（退化后的 FIFO）响应时间相同。

更一般的直观理解：
- SJF 中某作业的响应时间 = 排在它前面的所有更短作业的长度之和；
- RR 中某作业的响应时间 ≈ 它在就绪队列中的位置 × 量子。

要让二者相等，最直接的情形就是**所有作业等长、且量子等于该共同长度**（此时 RR 每个作业一次跑完，SJF 顺序也相同），二者响应时间一致。

## Q6. 随着作业长度增加，SJF 的响应时间会怎样？用模拟展示趋势

**答**：SJF 的平均响应时间随作业长度**线性增长**。原因是：在 SJF 中，一个作业的响应时间 = 排在它前面的所有更短作业长度之和；当所有作业长度整体放大 k 倍时，这个"和"也放大 k 倍，所以平均响应时间也放大 k 倍。

**趋势数据（SJF，同一比例 1:2:3）**：

| 工作负载 | 平均响应时间 | 平均周转时间 |
|---|---|---|
| `-l 10,20,30` | 13.33 | 33.33 |
| `-l 100,200,300` | 133.33 | 333.33 |
| `-l 1000,2000,3000` | 1333.33 | 3333.33 |

**验证命令**（原始输出见 `data/q6_sjf_10_20_30.txt`、`data/q6_sjf_1000_2000_3000.txt`）：
```
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p SJF -l 10,20,30 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p SJF -l 100,200,300 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p SJF -l 1000,2000,3000 -c
```

**结论**：负载整体放大 10 倍，平均响应/周转也约放大 10 倍，呈线性关系。

## Q7. 随着量子长度增加，RR 的响应时间会怎样？写出 N 个作业时最坏情况响应时间的方程

**答**：RR 的平均响应时间随量子 q **线性增大**——每个作业首次运行前，都要等队列中排在它前面的作业各跑一个量子；量子越大，等待越久。直到 q 超过最长作业长度，RR 不再抢占、退化为 FIFO，响应时间达到最大。

**趋势数据（工作负载 100,200,300，RR）**：

| 量子 q | 平均响应时间 | 平均周转时间 |
|---|---|---|
| 1 | 1.00 | 465.67 |
| 10 | 10.00 | 456.67 |
| 100 | 100.00 | 366.67 |

**验证命令**（见 `data/q7_rr_q1.txt`、`data/q7_rr_q10.txt`、`data/q7_rr_q100.txt`）：
```
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p RR -l 100,200,300 -q 1 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p RR -l 100,200,300 -q 10 -c
python3 ./ext/ostep-homework/cpu-sched/scheduler.py -p RR -l 100,200,300 -q 100 -c
```

**最坏情况响应时间方程**：

给定 N 个作业、量子长度为 q（作业长度均 ≥ q，全部已就绪），最坏情况下（排在队尾的那个作业）需要等前面 N−1 个作业各占一个量子后才第一次运行：

```
R_worst = (N − 1) × q
```

**结论**：量子放大 10 倍，平均响应时间也约放大 10 倍（线性）；而周转时间反而下降（因抢占减少、作业更连续地运行）。
